# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static site of printable HTML recipe cards, generated by the `recipe-card` Claude skill and hosted via GitHub Pages (Settings → Pages → deploy from branch `main`, root folder). There is no build system, package manager, linter, or test suite — everything is plain HTML with inline CSS.

- `index.html` — the directory page listing every recipe.
- `recipes/` — one self-contained HTML card per recipe (no external assets; multi-recipe files put each card on its own printed page).
- `skill/recipe-card/` — the **source of truth** for the skill that generates the cards: `SKILL.md` (the skill instructions) and `assets/template.html` (the house-style worked example). Edit these files directly.
- `skill/recipe-card.skill` — the packaged skill, a ZIP archive of `skill/recipe-card/`. Never edit it by hand; regenerate it after any source change (see below).

## Common commands

Preview the site locally:

```sh
open index.html            # or any card in recipes/
python3 -m http.server     # to test relative links as served
```

Repackage the skill after editing `skill/recipe-card/` (the archive must keep `recipe-card/` as its top-level folder):

```sh
(cd skill && zip -rFS recipe-card.skill recipe-card -x "*.DS_Store")
```

If the `skill-creator` skill is installed (`~/.claude/skills/skill-creator`), prefer its packager — it validates the frontmatter before zipping:

```sh
python3 -m scripts.package_skill /path/to/repo/skill/recipe-card /path/to/repo/skill  # run from the skill-creator directory; needs pyyaml
```

## Adding a new recipe

1. Drop the self-contained card into `recipes/` (naming: `<dish-name>-recipe-card.html`).
2. In `index.html`, copy an `<a class="card">` block near the top of `.grid` (newest first — a comment in the file shows the pattern) and update href/kind/title/desc/source.
3. Set `data-tags` on the block to its recipe types (space-separated, matching the `data-filter` values of the chips in `.filters`; add a new chip there if the recipe introduces a new type). Cards with `data-sub="<tag>"` appear only when that type's chip is selected, not under "All" — used for recipes that also exist inside a combined multi-card file, so the combined card represents them in the "All" view.
4. Bump the recipe count in the `index.html` footer (count recipes, not files — a combined file and its per-recipe splits count once).

## Card conventions

All cards share the house style defined in the skill's `assets/template.html` and repeated across existing cards: the CSS variable palette (`--ink`, `--muted`, `--accent`, `--accent-soft`, `--line`, `--cream`), Georgia serif titles, and print-friendly layout. When editing or creating cards, follow the layout rules in SKILL.md's "Keeping everything on the page" section — they are mandatory:

- Fluid on screen (`width: 100%; max-width: 210mm`); lock the fixed A4 sheet only inside `@media print`. Every card has exactly one `@media print` block.
- Grid/flex columns must be shrinkable: `minmax(0, 1fr)` tracks and `min-width: 0` on children; `overflow-wrap: anywhere` on titles and list items.
- Collapse two-column layouts to one column around `max-width: 560px`, restoring columns in print; use `break-inside: avoid` so ingredient groups/steps don't split across page breaks.

Extraction fidelity rules also live in SKILL.md: never invent ingredients, steps, quantities, or macros; preserve original order, groupings, and exact quantities/units. Any change to how cards are generated belongs in SKILL.md/template.html inside the `.skill` archive, not just in individual card files.
